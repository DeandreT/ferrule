Chapter 4

Supported formats

Format adapters translate external documents into `ir::Instance` and write target instances back out. Extension dispatch covers common cases; embedded format options carry dialects, layouts, and schemas.

Boundaries

  • PDF output is intentionally unsupported.
  • XBRL taxonomy formula, presentation, calculation, and linkbase execution are not interpreted.
  • XML preserves declared expanded names, and MFD export writes foreign declarations as an atomic local XSD graph. Mapping paths use local field names, so XSD import explicitly rejects siblings that differ only by namespace. Optional/unbounded named model groups with exactly one nonrepeating member flatten to that member's repeated field. Exact optional/unbounded ##local element wildcards declared inline or through named model groups, and direct or named-attribute-group ##local attribute wildcards with processContents="skip", are supported; other namespace-aware or validating wildcard shapes remain outside the subset.
  • JSON Schema flattens compatible allOf branches and preserves heterogeneous scalar type arrays, exact scalar anyOf, pairwise-disjoint scalar oneOf, identical or scalar-domain-subsumed array anyOf branches, selected object alternatives, nullable scalar/object/array wrappers, and typed or unconstrained dynamic properties. Omitted or true additionalProperties retains arbitrary JSON-valued fields, schema-valued declarations retain their exact dynamic type, and explicit false rejects undeclared input properties instead of dropping them. Canonical export preserves that open, typed-open, or closed contract, and compatible allOf intersections cannot widen a closed branch. Bounded scalar const/enum sets, exact integer or finite-number ranges, positive finite decimal multipleOf constraints, exact minItems/maxItems array intervals, exact minProperties/maxProperties object intervals, exact structural uniqueItems, exact minLength/maxLength string intervals, and portable pattern assertions are enforced on input and normalized output. uniqueItems compares complete values, ignores object member order, preserves nested array order, and treats mathematically equal supported integer/number values as duplicates. Inside private contains and dependentSchemas predicates, uniqueItems rejects item shapes that admit non-integral number values or arbitrary JSON, including through nested fields, until predicate matching can retain raw numeric lexemes. Closed integer, string, boolean, and object item shapes remain supported. Allowed-value sets may combine strings, booleans, signed integers, exactly representable finite numbers, and JSON null; references and compatible allOf intersect them, finite scalar anyOf unites them, and finite scalar oneOf retains values admitted by exactly one branch. Structured enum members remain unsupported. multipleOf uses exact canonical decimal arithmetic without epsilon comparison; compatible allOf conjunctions and exact anyOf disjunctions survive. Contiguous same-type numeric range branches normalize to one exact interval when their divisor constraints are identical, while unions that correlate different numeric ranges with different divisors reject rather than widen. String assertions remain conditional on string runtime values in scalar unions; null bypasses them. They survive references according to each resource's dialect, compatible allOf conjunction, exact anyOf disjunction, disjoint scalar oneOf, array items, typed dynamic properties, and canonical export. Ferrule's Unicode-scalar pattern language supports anchors, dot, classes and ranges, alternation, groups, standard and counted repetition, lazy suffixes, and explicit character/Unicode escapes. Backreferences, lookaround, named groups, inline flags, Unicode properties, shorthand classes, octal/control escapes, and class-set operators reject rather than vary by backend. Programs, schema metadata, and each JSON document parse or serialization call's matching work are bounded; native and generated Rust/C# use the same matcher. JSON Lines validates root item counts, each object row property count, and each string item across all nonblank lines. Unknown and empty string format annotations are retained exactly on string-capable values and array items, including through compatible compositions and references, but named format vocabularies are not asserted at runtime. Annotations on non-string values and arbitrary-JSON nodes are syntactically validated but not retained. Annotation metadata is bounded to 64 distinct values, 1 KiB each and 16 KiB total per node. $ref siblings follow the dialect declared by each physical schema resource: Draft 4, 6, and 7 ignore them, while Draft 2019-09, 2020-12, and schemas without $schema apply Ferrule's supported sibling metadata and assertions. Unsupported modern structural intersections reject explicitly, and external resources select their own policy. unevaluatedProperties, heterogeneous or correlated numeric-range scalar unions, disjoint count or string-length unions, independently constrained nested array wrappers, general heterogeneous array composition, mixed structural unions, and other validation keywords remain outside the runtime.
  • A nonempty patternProperties map is exact for an explicitly typed object or object | null with additionalProperties: false when every bounded portable selector has one identical exactly representable value schema. Scalar, structured object, and homogeneous array values reuse the ordinary supported JSON value profile. Selectors are ORed in declaration order. A matching fixed property must have that schema; nonmatching fixed properties may differ. Runtime decoding chooses fixed properties first, then applies the selectors to remaining names. propertyNames independently checks every key. Dependency rules whose triggers are neither fixed nor selected normalize away as semantically unreachable, and nullable object null bypasses the object rules. Native and generated Rust/C# input, normalized output, and JSON Lines boundaries share the portable matcher and per-document work budget. Canonical export and re-import preserve the selector map and closed fallback; an empty map is a no-op. Distinct selector schemas, open or typed fallbacks, general overlap intersection, value shapes outside the ordinary exact JSON profile, and active allOf, object-alternative, or structural $ref-sibling composition reject explicitly.
  • Object property-count intervals count distinct parsed input properties before required-property and openness checks, including explicit JSON null and undeclared names; duplicate names use the parser's last value and count once. Output counts normalized members after absent Ferrule values are omitted. Nullable object null bypasses the interval; compatible allOf intersects it, and object alternatives retain only one common effective interval.
  • Object property dependencies require every dependent name whenever its trigger is present. Explicit JSON null counts as input presence; output checks normalized members after absent Ferrule values are omitted. Nullable object null bypasses the relation, compatible allOf unites rules, and object alternatives must retain one identical relation. Modern dependentRequired and legacy property-array dependencies import into the same bounded model and export canonically. Each object is limited to 256 triggers, 4,096 edges, and 256 KiB of property-name text, and unconditional required-property closure must remain feasible under its closed shape and maxProperties.
  • Schema-valued legacy dependencies and modern dependentSchemas apply a retained schema to the complete object whenever their trigger property is present. The containing schema must have a concrete object shape; a typeless schema that also admits non-object values rejects rather than narrowing those values away. Required-only predicates lower to ordinary property dependencies; nontrivial predicates keep supported scalar, object, array, pattern, and recursively bounded nested dependent-schema constraints. Explicit null activates a rule, normalized output is checked after absent-value omission, nullable object null bypasses the rules, and JSON Lines checks each object row. Repeated triggers remain conjunctive. Canonical export groups contiguous rules for one trigger with an inner allOf; ordered outer allOf branches preserve interleaved repeated-trigger order through re-import. Alternatives require an identical effective set. Each object retains at most 32 predicates and 256 KiB of trigger text. Predicate patterns share the document work budget. Draft 7, 2019-09, 2020-12, and schemas without $schema also support an exact conditional on an explicitly typed object schema whose if tests the presence of exactly one required property and whose then fits the supported dependent-schema predicate subset. A nullable outer object is supported with an absent or true else only when the if explicitly proves type: "object". Exact else: false requires a trigger that can be represented as an ordinary required field; it removes the nullable bypass when the false branch rejects null and retains any supported then dependency. It does not combine with existing object alternatives, and a closed object must already declare the trigger. Canonical export writes required and, when then retains a dependency, dependentRequired or dependentSchemas as appropriate. Value-sensitive, multi-trigger, general-if, other nontrivial else, unevaluated keywords, and heterogeneous positional arrays remain unsupported. Declared Draft 4/6/7 resources use legacy dependencies and ignore modern dependency keywords; Draft 4 requires object-form schemas, while Draft 6/7 also accept boolean schemas. Declared 2019-09/2020-12 resources use modern dependency keywords and ignore legacy dependencies. Resources without $schema intentionally accept both dependency spellings with modern reference-sibling behavior.
  • Object propertyNames constraints inspect every actual key, including declared, runtime-named, and empty-string properties. Raw parsed input keys and normalized emitted keys are checked. Exact false rejects every nonempty object; true and unconstrained schemas normalize away. Nullable object null bypasses the assertions, and each JSON Lines object row is checked independently. Finite const/enum name sets and their exact finite not complements, Unicode-scalar minLength/maxLength, bounded portable pattern conjunctions/disjunctions and their exact complements, and nonasserting ordered format annotations are retained. Draft 4 resources ignore the keyword; Draft 6 and newer resources apply it. Finite domains are limited to 4,096 names, 256 KiB per name, and 1 MiB total, while patterns share the document matcher budget. Correlated predicates and complements involving length, format, or mixed assertions reject rather than widen.
  • Array contains assertions retain a bounded conjunction of schema-shaped item predicates and exact match-count intervals. Plain contains defaults to one or more matches; Draft 2019-09 and newer minContains/maxContains set explicit bounds. Raw parsed members and normalized emitted members are counted, nullable array null bypasses the assertions, and predicate patterns share the document matcher budget. Compatible allOf branches append their assertions. Array alternatives retain only identical assertions or an exact containment relation rather than weakening correlated predicates and intervals. Draft 4 ignores contains; Draft 6/7 apply the default minimum and ignore the newer modifiers.
  • Ferrule supports an exact bounded homogeneous prefixItems subset for Draft 2020-12 and schemas without $schema. Every entry in the bounded finite prefix must normalize to one identical, non-repeating item shape. The tail must use that same shape, be false so the prefix length becomes an exact maxItems, or be provably unreachable under an existing maximum; an unconstrained tail is also exact when the common prefix shape accepts arbitrary JSON. Heterogeneous entries or tails, conflicting count bounds, concrete nested-array entries, and active unevaluatedItems reject rather than widen. Canonical export writes the equivalent ordinary items schema plus maxItems for a closed tail, so no tuple-specific runtime or mapping IR is required. Draft 4 through Draft 2019-09 treat prefixItems as unknown.
  • The complementary bounded homogeneous legacy tuple profile accepts array-valued items in Draft 4, 6, 7, and 2019-09 resources and in schemas without $schema. Each tuple contains 1 to 4,096 positional members, all of which normalize to one identical, non-repeating item shape. The additionalItems tail must use that shape, be false so the tuple length becomes maxItems, or be provably unreachable under an existing maximum. An absent or true tail is exact only for an arbitrary-JSON item shape or when the maximum makes the tail unreachable. Explicit and derived item-count intervals are intersected, and contradictions reject. Canonical export writes ordinary schema-valued items plus maxItems when closed, so no positional-array runtime or mapping IR is retained. Draft 2020-12 requires schema-valued items; array-valued items are rejected there rather than being treated as prefixItems. Heterogeneous members, reachable heterogeneous tails, and concrete nested-array members remain unsupported.
  • Database execution is SQLite-specific today.
  • EDI output validation runs after wire lexical formatting and leaves the destination unchanged on failure.
