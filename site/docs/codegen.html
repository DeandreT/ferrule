Chapter 6

Rust and C# code generation

ferrule lowers the portable subset of a validated project into a buildable mapping library. Rust and C# share the same neutral program so successful generation preserves evaluation order, Null behavior, output shape, and typed failures.

C#

cargo +nightly run -p cli -- generate \
  --project project.json \
  --language csharp \
  --out generated-csharp

The result is a standalone, package-free .NET 10 library. Runtime sources are vendored into the generated artifact tree, and named inputs, outputs, and bounded host parameters use typed boundary methods.

Rust

cargo +nightly run -p cli -- generate \
  --project project.json \
  --language rust \
  --out generated-rust \
  --rust-runtime-path crates/codegen-runtime

Rust generation currently links the local codegen-runtime crate by path. The generated crate exposes primary-output entry points plus output-set and named-source variants. Its execution context can borrow a validated RuntimeParameters set.

JSON application boundary

Both generated libraries can accept and return ordinary JSON text. The mapping embeds its source, named-source, primary-target, and named-target schemas, so a host does not need to manually construct ferrule instance trees for a JSON workflow.

Heterogeneous scalar unions retain their string, integer, floating-point, or boolean runtime tag. Numeric adaptation is allowed only when the value is exactly representable; ambiguous coercions and lossy output fail through the same typed boundary contract in Rust and C#.

Rust

let outputs =
  execute_json_outputs_with_sources(
    source_json,
    &[NamedJsonInput {
      name: "catalog",
      document: catalog_json,
    }],
  )?;

C#

var outputs =
  GeneratedMapping
    .ExecuteJsonOutputsWithSources(
      sourceJson,
      new[] {
        new NamedJsonInput(
          "catalog", catalogJson)
      });

Input names remain exact and duplicate-checked, while named outputs retain project order. Context-aware overloads accept the same mapping paths, stable date-time, and typed runtime parameters as the instance-tree APIs.

Bounded documents. Each JSON input and output is capped at 64 MiB and each trusted embedded schema at 1 MiB. Invalid shapes, numeric conversions, scalar constants, bounded exact scalar allowed-value sets, exact numeric ranges and decimal multipleOf constraints, array item-count and contains match-count intervals, object property-count intervals, object property dependencies and dependent-schema predicates, property-name constraints, exact closed homogeneous patternProperties, structural uniqueItems, Unicode string-length intervals, bounded portable JSON Schema pattern assertions, exact open/closed object contracts, output serialization, and size excess produce typed boundary failures in both Rust and C#. These methods are deliberately JSON-only; stored format paths and options remain host metadata.

Omitted or true additionalProperties preserves arbitrary JSON-valued fields, schema-valued declarations validate unknown fields against their retained type, and explicit false reports an undeclared property instead of silently dropping it.

Embedded schemas retain a nonempty patternProperties map exactly for an explicit object or object | null with additionalProperties: false when every bounded portable selector has one identical exactly representable value schema. Scalar, structured object, and homogeneous array values reuse the ordinary supported JSON value profile. Selectors are ORed in declaration order. Matching fixed properties must share that schema; nonmatching fixed properties may differ. Generated decoding chooses fixed properties first, while propertyNames remains independent. Dependency rules whose triggers are neither fixed nor selected normalize away as semantically unreachable, and nullable null bypasses object checks. Rust and C# enforce input, normalized output, and JSON Lines with the shared per-document pattern work budget. Canonical export and re-import preserve the selector map; an empty map is a no-op. Distinct selector schemas, open or typed fallbacks, general overlap intersection, value shapes outside the ordinary exact JSON profile, and active allOf, object alternatives, or structural $ref siblings remain outside the profile.

Exact object minProperties/maxProperties intervals count distinct parsed input properties before decoding and normalized output members after absent Ferrule values are omitted. Duplicate input names use the parser's last value and count once. Nullable object null bypasses the interval; nested, repeated, primary, and named documents apply the same rule.

Embedded array contains assertions count members accepted by each retained item predicate. Plain assertions require at least one match, while retained minContains/maxContains intervals apply exactly. Input checks the parsed array and output checks the normalized emitted array; nullable array null bypasses the assertions. Multiple compatible allOf assertions are conjunctive, and predicate pattern matching shares the bounded document work budget. Count mismatches remain typed input/output boundary errors, while invalid embedded metadata and matcher work exhaustion remain fatal.

The exact homogeneous prefixItems importer subset adds no generated-runtime feature or new code-generation IR form. Draft 2020-12 and undeclared schemas whose bounded finite prefix entries normalize to one item shape lower to the existing repeated-item schema and item-count interval. A closed tail becomes the equivalent maxItems bound, and canonical export uses ordinary items plus that bound. Rust and C# therefore execute the existing homogeneous array boundary; heterogeneous prefixes and tails remain import-time rejections.

Homogeneous legacy tuple-form items uses the same lowering for Draft 4, 6, 7, and 2019-09 resources and for schemas without $schema. Its 1 to 4,096 identical positional members become one repeated-item schema. A false additionalItems tail becomes maxItems at the tuple length; an identical tail remains unbounded. An absent or true tail is accepted for an arbitrary-JSON item shape or when the explicit maximum makes the tail unreachable; a different schema tail requires that same maximum proof. Canonical export again uses schema-valued items and an optional maxItems, so generated Rust and C# need no positional-array IR or runtime path. Draft 2020-12 array-valued items and all reachable heterogeneous positional shapes reject during import.

Embedded object property dependencies are enforced on input and normalized output too. Whenever a trigger property is present, every dependent property must be present. Explicit JSON null counts as presence on input; output checks after absent Ferrule values are omitted. Nullable object null bypasses the relation, while nested, repeated, primary, and named documents all use the same rule.

Embedded whole-object dependent-schema predicates use the same property-presence rule. Required-only entries lower to ordinary property dependencies; other retained predicates validate the complete containing object. Repeated triggers remain conjunctive, predicate patterns share the document work budget, and malformed metadata remains a typed boundary failure. Text and UTF-8 byte entry points enforce the same primary and named input/output behavior. Draft 7, 2019-09, 2020-12, and undeclared explicitly typed object schemas may spell one such rule as an if with exactly one required-property presence trigger and a supported then predicate. A nullable outer object is supported with an absent or true else only when the if explicitly proves type: "object". Exact else: false requires a trigger that can be represented as an ordinary required field; it removes the nullable bypass when the false branch rejects null and retains any supported then dependency. It does not combine with existing object alternatives, and a closed object must already declare the trigger. Import lowers these forms to required plus dependentRequired or dependentSchemas metadata as appropriate, so generated Rust and C# need no separate conditional runtime. Value-sensitive, multi-trigger, general-if, and other nontrivial else schemas remain unsupported.

Embedded propertyNames constraints inspect every actual key instead of schema placeholders. Exact false, finite allowed-name sets, Unicode-scalar length, portable patterns, and nonasserting format annotations are retained. Raw parsed input keys and normalized emitted keys are checked, including runtime-named and empty-string properties. Nullable object null bypasses the assertions.

Both generated runtimes evaluate multipleOf through the same canonical decimal coefficient and exponent model, without floating-point tolerance. Compatible conjunctions and exact disjunctions therefore retain identical Rust and C# behavior.

JSON Schema patterns use Ferrule's Unicode-scalar Thompson-NFA matcher in both generated runtimes. It supports anchors, dot, character classes and ranges, alternation, groups, ordinary and counted repetition, lazy suffixes, and explicit character or Unicode escapes. Nonportable constructs such as backreferences, lookaround, named groups, inline flags, shorthand classes, and Unicode properties reject before execution. Compilation, embedded metadata, and one shared matching-work budget per JSON document parse or serialization call are bounded. Mapping-language regex tokenization is separate and still uses the documented Rust/.NET backend subset.

Run the examples

The repository includes one mapping project with matching Rust and C# hosts. From the repository root, generate both libraries, build both hosts, and verify both results with one command: 

./examples/codegen/run.sh

The runner reads examples/codegen/project.json, writes disposable artifacts below examples/codegen/generated/, and then executes each host against the same input. This keeps the example focused on the application boundary: pass JSON text, call the generated mapping, and handle its bounded result.

The mapping removes zero-value orders, sorts the remaining rows, assigns compact output positions, and formats invoice labels. input.json and expected-output.json show the equivalent JSON boundary values.

Generate and run Rust only

find examples/codegen/generated/rust -depth -delete 2>/dev/null || true
cargo +nightly run -p cli -- generate \
  --project examples/codegen/project.json \
  --language rust \
  --out examples/codegen/generated/rust \
  --rust-runtime-path crates/codegen-runtime

cargo +nightly run \
  --manifest-path examples/codegen/rust/Cargo.toml

Generate and run C# only

find examples/codegen/generated/csharp -depth -delete 2>/dev/null || true
cargo +nightly run -p cli -- generate \
  --project examples/codegen/project.json \
  --language csharp \
  --out examples/codegen/generated/csharp

dotnet run \
  --project examples/codegen/csharp/Ferrule.CodegenExample.csproj \
  --configuration Release
Generated trees are build artifacts. Change the shared project or either host, then rerun the script. The checked-in example owns the mapping and integration code; generation recreates the language-specific libraries from that source.

Portable subset

  • Scalar constants, ordinary and frame-pinned source fields, positions, lazy conditionals, value maps, lookups, schema-guided JSON-string field projection and typed object serialization, embedded delimited FlexText field projection, collection and raw/filtered/per-item-computed generated-sequence aggregates, and a closed scalar function set.
  • Primary and static named sources, one primary target, and ordered named targets.
  • Nested source iteration, generated scalar sequences, filters, multi-key sorting, sequence windows, grouping, mapped output, bounded recursive-filter, path-hierarchy, and adjacency-tree target construction, and compact positions.
  • Structured XML serialization and ordered mixed-content reconstruction with graph-computed replacements.
  • Root-context static inner joins plus bounded per-item joins anchored by one or more current-item scalar fields and optionally augmented with independent primary/named singleton scalars and repeating sources, with duplicate-preserving order and exact joined fields.
  • Typed runtime errors for arity, scalar types, missing or invalid host parameters, functions, aggregate bounds, generated sequence limits, and unsupported reachable constructs.
  • Typed reusable scalar user functions, including nested calls and access to the same stable runtime values and bounded host parameters as the main graph.
Generation is conservative. Unsupported reachable constructs are reported before artifacts are created. Unreachable graph nodes do not block an otherwise portable project.

Output safety

The CLI validates and stages a complete artifact tree before publishing it. Generation requires a destination that does not already exist, avoiding partial replacement of user-managed source trees.
