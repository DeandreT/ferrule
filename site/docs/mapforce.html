Chapter 5

MapForce import/export

ferrule provides clean-room, best-effort import and export for MapForce `.mfd` designs. Unsupported pieces become warnings where possible, so recoverable mappings stay editable and executable.

Import a design

cargo +nightly run -p cli -- import-mfd \
  --mfd design.mfd \
  --out project.json

When mapping resources live outside the design directory, pass --package-root package. For separately managed EDI releases, repeat --edi-catalog-root DIR in search order. Separately managed JSON Schema releases use repeatable --json-schema-root DIR. Package resources take precedence. Windows separators and leading installation-relative parent locators are re-anchored under each catalog, while every resolved file and nested schema reference remains canonically confined to its explicitly trusted root.

Import resolves supported document components, schemas, graph nodes, target scopes, format options, paths, and warnings into a ferrule project. A design is rejected only when no usable source or target can be recovered.

Export a design

cargo +nightly run -p cli -- export-mfd \
  --project project.json \
  --out design.mfd

Export writes the representable project subset with generated schema, layout, or metadata siblings. Shapes that cannot be represented safely reject atomically instead of publishing partial wiring.

Representative coverage

  • XML, JSON, CSV, fixed-width, FlexText, XLSX, SQLite, EDI, Protocol Buffers, XBRL, HTTP XML, and visual PDF source components.
  • Core scalar functions, aggregates, lookups, joins, exceptions, generated sequences, value maps, grouping, sorting, and windows.
  • Native GUID generation, scalar or record-producing filter lookups over XML, EDI, and database inputs, and scalar UDF item selection, position-aware filtered matching, or raw/filtered/per-item-computed aggregate reduction over bounded tokenized or generated sequences.
  • Named static sources, dynamic XML paths, independent targets, schema-equal copy-all scopes, generic XML element sequences, selected user-function shapes, and bounded scalar modules from adjacent XSLT, C#, Java, and XQuery source.
  • Expanded XML element and attribute names survive import and execution; foreign declarations export atomically as deterministic local XSD dependency files.
  • Named XSD model/attribute groups and typed element, simple-content, and attribute defaults survive import, execution, export, and re-import.
  • Structured XML string serializers preserve attributes, nested and repeated content, escaping, namespaces, and declaration policy, and export with generated XSD contracts.
  • Structured XML SQLite text columns and declared local relations remain executable and round-trip with their typed database connection metadata.
  • External EDI configuration directories and adjacent bounded ZIP packages compile into portable X12 or EDIFACT runtime schemas.
  • Referenced JSON Schemas retain bounded exact scalar const/enum domains, exact integer and finite-number ranges, positive finite decimal multipleOf constraints, contains match-count intervals, and structural uniqueItems, including nullable fields, compatible compositions, canonical export, and matching native/generated enforcement.
  • Referenced JSON objects retain exact openness: omitted or true additionalProperties remains unconstrained, schema-valued declarations remain typed, and explicit false rejects undeclared input properties. Canonical MFD export and re-import preserves all three contracts.
  • Referenced schemas retain exact closed homogeneous patternProperties for an explicit object or object | null with additionalProperties: false. Every portable selector in a nonempty bounded map must share one identical exactly representable value schema. Scalar, structured object, and homogeneous array values reuse the ordinary supported JSON value profile. Selectors are ORed in declaration order, and matching fixed properties must share that schema. Runtime decoding chooses fixed properties first, while propertyNames remains independent. Dependency rules whose triggers are neither fixed nor selected normalize away as semantically unreachable, and nullable null bypasses object checks. Native and generated Rust/C# enforce input, normalized output, and JSON Lines with the shared pattern work budget. Canonical MFD schema export and re-import preserve the map; an empty map is a no-op. Distinct selector schemas, open or typed fallbacks, general overlap intersection, value shapes outside the ordinary exact JSON profile, and active allOf, alternatives, or structural $ref siblings produce an actionable fallback diagnostic.
  • Referenced JSON objects retain exact minProperties/maxProperties intervals through nullable wrappers, dialect-aware references, compatible allOf, and alternatives with one common effective interval. Native and generated Rust/C# enforce distinct parsed input-property and normalized output counts, while canonical MFD export and re-import preserves the interval.
  • Referenced JSON objects retain property dependencies and whole-object dependent-schema predicates through nullable wrappers, dialect-aware references, compatible allOf, and alternatives with one identical effective rule set. Modern dependentRequired and legacy property-array dependencies normalize to the same presence rule and canonical export uses dependentRequired. Required-only schema predicates lower to that relation; representable schema-valued legacy dependencies and modern dependentSchemas retain their complete object predicate, including recursively bounded nested rules, and export canonically. Contiguous repeated-trigger rules use an inner allOf, while ordered outer allOf branches preserve interleaved trigger order through re-import. Native and generated Rust/C# enforce raw input presence and normalized-output behavior. Draft 7, 2019-09, 2020-12, and undeclared explicitly typed object schemas may express the same rule as an if with exactly one required-property presence trigger and a supported then predicate. A nullable outer object is supported with an absent or true else only when the if explicitly proves type: "object". Exact else: false requires a trigger that can be represented as an ordinary required field; it removes the nullable bypass when the false branch rejects null and retains any supported then dependency. It does not combine with existing object alternatives, and a closed object must already declare the trigger. Import normalizes these forms to required plus dependentRequired or dependentSchemas metadata as appropriate, which canonical MFD schema export preserves. Value-sensitive, multi-trigger, general-if, other nontrivial else schemas, unevaluated property keywords, and heterogeneous positional array schemas still produce an actionable fallback diagnostic. Declared Draft 4/6/7 resources use legacy dependencies, declared 2019-09/2020-12 resources use modern dependency keywords, and resources without $schema intentionally accept both spellings with modern reference-sibling behavior.
  • Referenced JSON objects retain supported propertyNames schemas across import, canonical export, and re-import. Exact false, finite const/enum names, Unicode-scalar length, bounded portable patterns, and nonasserting format annotations execute against raw parsed and normalized emitted keys, including runtime-named and empty-string properties. Draft 4 resources ignore the keyword; Draft 6 and newer resources apply it. General correlated name unions and not produce an actionable fallback diagnostic.
  • Referenced JSON arrays retain bounded contains assertions through import, canonical schema export, and re-import. Plain assertions require at least one matching member; Draft 2019-09 and newer minContains/maxContains modifiers retain an exact match-count interval. Compatible allOf assertions remain conjunctive, nullable array null bypasses them, and predicate patterns use the same bounded document matcher budget as ordinary string constraints.
  • Referenced JSON arrays retain exact minItems/maxItems intervals through references, nullable wrappers, and compatible compositions.
  • Referenced JSON arrays using homogeneous legacy tuple-form items remain executable through MFD import. Draft 4, 6, 7, and 2019-09 resources, plus schemas without $schema, normalize 1 to 4,096 identical positional members to one repeated item shape. An identical additionalItems tail remains unbounded, while false closes the array at the tuple length. An absent or true tail is accepted for an arbitrary-JSON item shape or when an explicit maximum makes it unreachable; a different schema tail requires that same maximum proof. Canonical export writes schema-valued items and an optional maxItems, so export/re-import and generated Rust/C# use the existing homogeneous-array path. Draft 2020-12 array-valued items, contradictory counts, and reachable heterogeneous members or tails produce an actionable schema-fallback diagnostic instead of being treated as prefixItems.
  • Referenced JSON strings retain exact Unicode-scalar minLength/maxLength intervals and bounded portable pattern assertions through nullable wrappers, arrays, typed dynamic properties, dialect-aware references, compatible allOf, exact anyOf, disjoint scalar oneOf, canonical export, and opaque format annotations. Native and generated Rust/C# enforce the same input/output pattern semantics.
  • Unresolved external EDI configuration references survive export and re-import without being treated as executable runtime layouts.
Interop is intentionally resilient. The importer favors partial executable recovery with actionable diagnostics over all-or-nothing conversion.
